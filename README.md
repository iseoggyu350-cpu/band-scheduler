# 🎸 밴드 합주 시간표

교내 밴드부원들이 **밴드부 → 팀 → 내 이름**을 고르고, 가능한 시간을 칠하면 팀원들이 겹치는 합주 시간을 바로 찾아주는 웹앱입니다.

- **밴드부(소속)**: 관리자만 추가·수정·삭제할 수 있어요.
- **팀**: 곡별 팀이나 고정 팀. 학생 누구나 자기 밴드부 안에서 만들 수 있어요.
- **가능 시간**: 팀마다 따로 입력해요.
- 접속할 때마다 누구든 **밴드부 고르기부터** 시작해요. 고른 내용은 그 탭을 열어둔 동안만 기억해서 새로고침해도 그대로예요. 동아리방 컴퓨터처럼 여럿이 같은 기기를 써도 앞사람의 팀·이름이 남지 않아요.
- 팀원이 입력한 시간은 실시간으로 반영돼요. 실시간 연결이 안 되면 15초마다 자동으로 새로고침해요.

데이터는 [Supabase](https://supabase.com) 무료 플랜에 저장하고, 사이트는 GitHub Pages로 배포합니다.

---

## 처음 한 번만: 배포 설정 (관리자, 약 5분)

### 1. Supabase 프로젝트 만들기

1. <https://supabase.com> 에 GitHub 계정으로 가입하고 **New project**를 누릅니다.
2. 이름은 `band-scheduler`, Region은 **Northeast Asia (Seoul)** 을 고르고, DB 비밀번호는 아무거나 길게 정해서 만듭니다. (이 비밀번호는 앱에 쓰지 않아요.)

### 2. 데이터베이스 만들기

1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 저장소의 [`supabase/schema.sql`](supabase/schema.sql) 내용을 **전부** 복사해 붙여넣고 **Run**을 누릅니다.
3. 새 쿼리 창에서 관리자 코드를 정합니다. 따옴표 안을 원하는 코드로 바꿔서 실행하세요.

   ```sql
   select public.set_admin_code('여기에-관리자-코드');
   ```

   관리자 코드를 잊어버리면 이 줄을 새 코드로 다시 실행하면 돼요.

### 3. 앱에 Supabase 주소와 공개 키 넣기

1. Supabase 대시보드에서 **Project Settings → API Keys** (또는 **Data API**)로 갑니다.
2. **Project URL**과 **Publishable key**(`sb_publishable_...`)를 복사합니다.
   예전에 만든 프로젝트라면 `anon` `public` 키(`eyJ...`)를 써도 돼요.
3. 저장소의 [`config.js`](config.js)를 열어 두 값을 넣고 `main` 브랜치에 커밋합니다.

   ```js
   window.BAND_SCHEDULER_CONFIG = {
     supabaseUrl: 'https://abcdefghijklmn.supabase.co',
     supabaseKey: 'sb_publishable_xxxxxxxx',
     legacyGithubRepo: 'iseoggyu350-cpu/band-scheduler'
   };
   ```

> ⚠️ **secret 키나 `service_role` 키는 절대 넣지 마세요.** 공개(publishable/anon) 키는 원래 웹사이트에 들어가도 되는 키이고, 실제로 무엇을 할 수 있는지는 `schema.sql`의 보안 규칙이 막아줍니다.

### 4. 사이트 확인 & 밴드부 등록

1. GitHub Pages 주소(`https://iseoggyu350-cpu.github.io/band-scheduler/`)로 들어갑니다.
2. 첫 화면 아래의 **관리자**를 눌러 관리자 코드를 입력합니다.
3. **밴드부(소속)**를 추가합니다. 순서(▲▼)와 이름도 여기서 바꿀 수 있어요.
4. (선택) **예전 데이터 가져오기 → 불러오기**를 누르면 예전 GitHub 동기화 버전에 저장된 팀(`우리 밴드`, `똥펑크` 등)과 시간을 그대로 옮길 수 있어요. 가져올 밴드부를 고르고 **선택한 팀 가져오기**를 누르세요. 이미 옮긴 팀은 "이미 있음"으로 표시돼서 두 번 들어가지 않아요.

### 5. 단톡방에 공유

- **사이트 주소**를 보내면 → 밴드부 → 팀 → 이름 순서로 고르고 들어와요. 주소창에는 항상 첫 페이지 주소만 보여서, 주소창을 복사해 보내도 받은 사람은 첫 페이지부터 시작해요.
- 팀 화면의 **이 팀 링크 복사**로 만든 링크를 보내면 → 그 팀의 "누구신가요?" 화면으로 바로 들어와요. 이때도 이름은 각자 골라요.
- **결과 복사**로 복사한 추천 시간 요약 맨 아래에도 팀 링크가 붙어 있어요.

## 예전 버전(GitHub 동기화)을 쓰던 경우

- 예전 초대 링크(`#gh=...`)로 들어오면 링크 속 토큰은 바로 지워지고, 밴드부 고르기 화면으로 안내돼요.
- 예전 버전이 기기에 저장해 둔 GitHub 토큰도 새 버전이 처음 열릴 때 지웁니다.
- 예전 데이터를 다 옮긴 뒤에는 **GitHub의 예전 토큰을 폐기**하는 걸 추천해요. 단톡방 링크에 들어 있던 토큰이라서요.
  (GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → 해당 토큰 → Delete)

## 알아두면 좋은 것

- **누구나 팀·멤버·시간을 고칠 수 있어요.** 동아리 안에서 편하게 쓰도록 일부러 열어둔 거예요. 팀 삭제, 멤버 삭제, 시간 비우기는 확인 창이 한 번 더 떠요.
- **밴드부(소속) 추가·이름 변경·삭제·순서 변경**은 관리자 코드가 맞아야만 서버가 허락해요. 화면만 고쳐서는 우회할 수 없어요.
- **Supabase 무료 플랜**은 한동안(현재 기준 약 1주일) 아무도 접속하지 않으면 프로젝트가 일시정지될 수 있어요. 시험 기간처럼 오래 안 쓰다가 다시 쓸 때 사이트가 안 열리면, Supabase 대시보드에서 프로젝트를 **Restore**하면 돼요. 데이터는 그대로 있어요.
- `schema.sql`은 여러 번 실행해도 기존 데이터를 지우지 않아요. 나중에 앱이 업데이트되면서 스키마가 바뀌면 다시 실행하면 돼요.

## 파일 구조

| 파일 | 내용 |

| `index.html` | 화면 구조 |
| `app.js` | 앱 동작 (온보딩, 시간표, 추천, 동기화, 관리자) |

| `supabase/schema.sql` | 데이터베이스 테이블과 보안 규칙 |
